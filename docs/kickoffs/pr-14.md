```text
PR 14 (Shell and Dashboard). The design now follows Stock Trading
Agent: the same token structure, header, Needs you list, phone width
and Dashboard order. This PR builds that. Decisions, gates, sizing,
exits and the cycle don't change; the only backend work is the Needs
you list and a few read fields for the Dashboard. Start from the
latest main, with PR 13 merged. Read:
1. docs/CHANGES.md, entry 2026-11-03 "v0.3: screens and tools from
   Stock Trading Agent", and design/CHANGES.md, entry 2026-11-03
   "Aligned with Stock Trading Agent" (the token rename map and the
   build order for the design)
2. docs/SPEC.md → v0.3 → Shell and Dashboard (whole subsection) and
   Build order (v0.3); GUI screens → Dashboard; User features 2, 4, 6
   and 7 (quiet line, briefing, per-coin pause, risk budget)
3. design/DESIGN.md → The shell, Shared components, Rules, Interaction
   rules, Phone width
4. design/screens/Main.dc.html and States.dc.html (Card states,
   Toasts), and the header of every other screen; their PNGs at 1440
   and -390
5. AGENTS.md → hard rules (money as Decimal from the backend, no
   hard-coded thresholds, no real network calls in tests)

Build PR 14 only, in this order (one commit per step):

1. Tokens. Replace frontend/src/styles/tokens.css with design/tokens.css
   and rename every variable in app.css and the components with the
   map in design/CHANGES.md (a mechanical rename; nothing else changes
   in this commit). Remove --topbar. Chart series: EMA 20 #7FB8FF,
   EMA 50 #C792EA, VWAP #F2B94B dashed, through the --ta-chart-*
   tokens, on the Dashboard and Indicators charts.
2. Interaction CSS. The global rules at the end of tokens.css:
   :focus-visible, .ta-row, .ta-tile, .ta-skel with reduced motion,
   buttons brightening on hover. Apply .ta-row to clickable rows and
   .ta-tile to linked tiles. No outline: none anywhere without the
   focus ring.
3. Backend: Needs you.
   - One module computes the list from stored state (pure function plus
     a loader), most urgent first, in the order of the table in SPEC →
     v0.3 → Shell and Dashboard → Needs you. Each item: kind, title,
     detail, action label, action target (a route), since.
   - Sources: kill not acknowledged; pending approvals; open errors
     (the errors table, until PR 15); an API key or source with 3
     failures in a row (source registry); email: the SMTP host is
     empty while any event has email on, or the last send failed;
     an active market failing eligibility (target /settings#markets
     until the Markets screen, PR 17); cost cap at 80% or more.
   - Health line: time of the last closed Bitvavo candle, price stream
     state, clock offset (from Bitvavo's GET /time, at most once per
     cycle), OpenAI key status, collector status. If the app has no
     clock offset today, add it; it is information only and never
     blocks a cycle.
   - Recomputed each cycle and after every change to its inputs.
     Snapshot field `needs` (items + health) and GET /api/needs.
4. Backend: Dashboard read fields (all computed in Python, Decimal for
   money, sent as numbers or Decimal strings as today):
   - per open position: stop distance in % and in ATR(1h), P&L in R,
     and stop_above_entry;
   - since start: the account's return and holding BTC over the same
     period, from the function Performance and Readiness already use;
   - cycle counter: next cycle time, cycles done today and scheduled
     today, counted on the Amsterdam day (92, 96 or 100 on clock-change
     days), the run's cycle id;
   - today's decisions: decisions since 00:00 Amsterdam grouped by
     cycle, newest first, and inside a cycle by final action and
     reason, with a flag for changes (entries, exits, stop moves);
     name the endpoint yourself (for example GET /api/cycles/today);
   - Markets card: per active pair the price, 24h change, regime, the
     latest pre-filter result (passed, held, the failed condition,
     paused, warming up) and the last action (the newest decision today
     that wasn't a Rules no-call, or none).
5. Shell. A Header component replaces TopBar on every screen: title and
   sub line, PAPER badge (the Paper/Live switch goes), status pill with
   next cycle and minutes left, Needs you chip (hidden at 0), Equity,
   Today (€ and %), Regime (BTC), Ask (Ctrl/⌘+J), Pause/Resume, Stop &
   flatten. The Ask link leaves the sidebar. ErrorBadge goes; open
   errors are a Needs you item. Screen controls move into the page as
   in the screens: Performance period and export, Insights filters as
   a card, Settings Save and Discard in the sticky unsaved-changes bar.
   Run now moves to the cycle strip. The page title shows the state
   ("● Running · Trading Agent", "⏸ Paused · …", "⛔ Killed · …").
6. Dashboard in the new order, per Main.dc.html: Needs you card (with
   the health line; at 0 items only the health line), cycle strip,
   two tiles (model calls today with the daily budget bar; since start
   vs holding BTC), open positions with the stop-to-target bar next to
   the risk budget (add the exposure meter and the cooldown row), price
   chart (candles, EMA 20/50, VWAP from 00:00 UTC, entry/stop/target
   lines, held-pair buttons, Find pair, 1h/4h/1d) next to the latest
   decision ("Open full decision", per-coin pause stays), today's
   decisions next to the morning briefing (with its footer), Markets
   card (filters All, Pass rules, Held, Paused; search; a row charts
   the pair). PairTabs leaves the Dashboard. The News flag row and
   button in the risk budget ship with PR 10; leave them out until
   then.
7. Phone width. Below 820 px the sticky top bar (mark, title, Needs you
   count, Ask, menu) replaces the sidebar; the menu opens the sidebar
   as an overlay with the dialog focus rules. Every screen works at
   390 px: cards stack, wide tables scroll inside their card, no page
   scrolls sideways.
8. Card states and toasts. Every card that fetches data gets loading
   (skeleton, aria-busy), empty (only after a successful load, with
   the reason) and error (what failed and when, Retry, last data kept
   and marked stale). Two or more failing cards, or no API answer: the
   page banner, retrying every 15 s. In-app toasts for notification
   events per DESIGN.md → Interaction rules (one per event, at most 3,
   info and warning close after 10 s, critical stays, role alert for
   critical). Browser notifications stay as they are.

Tests (no network; fakes and the simulated market only):
- Needs you: one test per item kind (present when its cause is
  present, gone when it is gone), the order, and the empty list.
- Email item: SMTP host empty with an email event on → item; host set
  and last send ok → no item; last send failed → item.
- Cycle counter: a normal day (96), the last Sunday of March (92) and
  of October (100), counted on the Amsterdam day.
- Stop distance: in % and ATR, amber threshold at 1.5 ATR as a value
  from config; stop above entry gives stop_above_entry and no R loss.
- Today's decisions: grouping by cycle, then action and reason;
  changes always present in a folded cycle.
- Markets card: last action skips Rules no-calls.
- Frontend: Header renders the chip only when count > 0; the phone top
  bar replaces the sidebar below 820 px; the overlay traps focus and
  Escape closes it; card states for one card (loading, empty, error).
- Playwright: extend e2e/screenshots.spec.ts to every screen at
  1440 × 900 and 390 × 844, saved in docs/screenshots/pr-14/, and add
  a check that no screen scrolls sideways at 390 px.
```

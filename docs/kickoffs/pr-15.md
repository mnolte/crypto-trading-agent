Kickoff for Devin. Start the session with: "Build docs/kickoffs/pr-15.md."

```text
PR 15 (Error handling, logging and the Logs screen). Goal: any failure in
the app can be looked up afterwards (what failed, where, in which cycle
and on which pair, with which inputs, and what the app did about it), and
no error, warning or exception passes silently anywhere in the repository.
Logs go to a SQLite file, data/logs/logs.db, so the Logs screen can search
them. Decisions, gates, sizing, exits and the cycle don't change. Start
from the latest main, with PR 14 merged. Read:
1. docs/CHANGES.md, entry 2026-11-04 "v0.3: error handling and logs in
   SQLite", and design/CHANGES.md, entry 2026-11-04 "Logs screen"
2. docs/SPEC.md → v0.3 → Logging, errors and the Logs screen (the whole
   subsection: the failure catalogue is the contract for this PR);
   v0.3 → Shell and Dashboard → Needs you; The agent cycle and Market
   data and paper broker (the retry rules that already exist); OpenAI
   decision layer (timeout and retry); Settings, secrets and persistence
   → Operations; User features → Live-readiness checklist
3. design/DESIGN.md → Logs screen and Screens; design/screens/Logs.dc.html
   with Logs.png, Logs-390.png and Logs-trace.png; States.dc.html (card
   states, page banner)
4. AGENTS.md → hard rules (secrets never in logs, no real network calls
   in tests, never delete data/ or a log outside a test's own folder)

Build PR 15 only, in this order (one commit per step):

1. Audit. Write docs/analysis/2026-11-<dd>-error-handling-audit.md before
   changing code. List every try/except, background task, print() and
   silent failure path with file, line, what happens today and the fix
   (a catalogue row, or a question); every component's logging today
   and the INFO and DEBUG lines it needs; every external call with its
   timeout and retry today; what Ctrl+C does today during a cycle, a
   fill, a model call and a backup. Start from these, measured on main
   on 4 November:
   - silent catches: agent/engine.py:668 (clock offset, pass),
     engine.py:1147 (order book, return None), features/shadows.py:355
     (pass), shadows.py:595 (return None), features/whatif.py:232 (pass);
   - 54 `except Exception` in 14 files, most in agent/engine.py (20) and
     features/shadows.py (9);
   - bare create_task: main.py:230, 281, 284, 287, 289, 290, 292;
     agent/engine.py:182, 183; api/notifications.py:104, 132;
   - logging: operations.configure_logging writes INFO to a 10 MB
     app.log; only 9 of 110 modules have a logger;
   - print(): context/backfill.py (a CLI; say whether it stays).
   Commit the report alone. Anything that would change trading
   behaviour goes under "Questions" in the report and in the PR, not in

3. Event registry and tracing. backend/app/logevents.py with every event

   contextvars; cycle, watcher pass and job ids; X-Request-Id on every

4. Error handling, backend. backend/app/errors.py with the exception

   narrow every broad catch to the isolation boundaries in the spec;

Tests (no network; fakes, the simulated market and a fake clock):
- Store: lines land in logs.db with every column; search finds a word in
  the message and in exc_message; a batch commits within 1 s; an ERROR
  commits at once; the queue drops DEBUG before INFO and never WARNING
  and up; logs.db read-only → fallback file and stderr, then imported
  once it is writable again; retention removes by level and age, and
  DEBUG first above the size cap (with a small cap in the test).
- Scrubbing: a stored key, the SMTP password, a bearer token and an
  Authorization header never reach logs.db, the console or the fallback
  file, also inside an exception message.
- Registry: an unregistered event fails; a WARNING-or-up event without
  "what to do" fails.
- Tracing: a line written inside a spawned task during a cycle carries
  the cycle id and pair; an API response has X-Request-Id and a 500
  carries the same error_id as its log line.
- Catalogue: one test per row (the failure is injected through a fake
  client or the simulated market; the test checks the outcome, the
  level, the event and that the cycle or loop goes on).
- Hooks: an exception in a thread, an un-awaited task, a scheduler job
  and a warnings.warn() all reach logs.db; a bare asyncio.create_task
  outside spawn() fails a test (an AST check is fine); a task that keeps
  crashing is restarted with backoff and is CRITICAL after 5 in 10
  minutes.
- Timeouts: a fake client that never answers is cut off at its
  configured timeout for each external call.
- Problems: the fingerprint groups "BTC-EUR … 30 s" and "ETH-EUR … 31 s";
  a fixed problem that comes back is unreviewed; review needs a note.
- Shutdown: SIGINT during a fill leaves the fill and its position update
  both stored or both absent; the final line is "Shutdown complete";
  a leftover lock file gives the unclean-start WARNING.
- errors import: rows land once as problems with their state; a second
  start does not import again.
- Frontend: the API client shows the error id in a card error; the
  boundary renders "Something went wrong" with the id; client reports
  stop at 10 a minute; the Logs screen's level toggles, trace banner and
  opened line.
- Playwright: Logs at 1440 × 900 and 390 × 844, and the trace view, in
  docs/screenshots/pr-15/; no sideways scroll at 390 px.

- put screenshots in design/.
```
